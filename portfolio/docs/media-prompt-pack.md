# Career Studio Media Prompt Pack

이 문서는 최종 생성 자산으로 교체할 때 사용하는 제작 계약이다. 현재 저장소의 미디어는 런타임과 검증을 위한 추상 프로토타입이며, 모든 공개 화면에는 `RECONSTRUCTION / 비식별 재구성`을 유지한다.

## 공통 아트 디렉션

- 따뜻한 오프화이트 스튜디오, 차콜 구조선, 절제된 청회색 포인트.
- 건축 모형과 편집 디자인이 결합된 물리적 세트. 현실적인 재질, 부드러운 북향광, 얕은 그림자.
- 회사 로고, 실제 서비스 UI, 읽을 수 있는 가짜 문구, 인물, 개인정보를 사용하지 않는다.
- 패널은 추상적인 그리드·카드·모듈만 사용한다. 화면 중앙은 영상 크롭을 고려해 여유를 둔다.
- 데스크톱 16:9와 모바일 9:16은 같은 오브젝트·조명·카메라 축을 공유한다.

## 네거티브 규칙

`logo, brand mark, readable interface text, fake screenshot, personal information, portrait, neon cyberpunk, particle effects, heavy bloom, excessive blur, glossy sci-fi HUD, illegible typography, watermark`

## 장면 이미지 프롬프트 12개

각 항목을 16:9와 9:16으로 한 번씩 생성한다.

1. `01-megastudy`: 콘텐츠 카드와 제작 규칙이 얇은 금속 레일 위에서 하나의 작업 흐름으로 정렬된 편집 스튜디오.
2. `02-bucketstore`: 크기가 다른 이미지 플레이트가 반응형 그리드에 맞춰 재배치되는 라이트박스 세트.
3. `03-lotte`: 반복 가능한 카드 모듈과 두 개의 추상 기기 프레임이 맞물린 템플릿 시스템.
4. `04-chabio`: 기사 계층을 나타내는 종이 아카이브, 명확한 여백과 읽기 순서가 보이는 구조.
5. `05-hama`: Vue 컴포넌트를 암시하는 블록과 SCSS 토큰 플레이트, 다국어 레이어의 규칙적인 적층.
6. `06-synthesis`: 앞선 다섯 구조물이 하나의 조립 테이블 위에서 규칙·모듈·도구의 흐름으로 연결된 장면.

파일명:

- `desktop/static/01-megastudy.webp` … `06-synthesis.webp`
- `mobile/static/01-megastudy.webp` … `06-synthesis.webp`

## 모션 프롬프트 22개

장면 클립은 5초, 이동 클립은 4초다. 카메라는 느린 돌리 또는 2–4도의 오빗만 사용하고 오브젝트 변형은 최소화한다.

### 장면 6개 × 2

1. `01-megastudy`: 카드 레일을 따라 천천히 전진, 포커스가 규칙 플레이트에서 콘텐츠 모듈로 이동.
2. `02-bucketstore`: 이미지 플레이트 사이를 낮게 이동하며 가로 그리드가 세로 스택으로 정돈됨.
3. `03-lotte`: 공통 카드 모듈을 중심으로 작은 오빗, 두 기기 프레임의 깊이 차만 드러냄.
4. `04-chabio`: 종이 아카이브의 읽기 순서를 따라 오른쪽으로 느린 트래킹.
5. `05-hama`: 적층 블록 사이로 부드럽게 상승하며 컴포넌트 간격을 보여 줌.
6. `06-synthesis`: 조립 테이블에서 천천히 후퇴해 전체 시스템의 연결 관계를 공개.

각 모션을 동일한 시작·종료 프레임 계약으로 데스크톱과 모바일에 적용한다.

### 이동 5개 × 2

1. `megastudy → bucketstore`: 레일 끝을 따라 이동해 이미지 플레이트가 있는 다음 테이블에 진입.
2. `bucketstore → lotte`: 이미지 그리드 사이를 통과하며 카드 모듈 구조로 자연스럽게 전환.
3. `lotte → chabio`: 기기 프레임의 모서리를 지나 종이 아카이브의 수평선에 정렬.
4. `chabio → hama`: 종이 레이어가 입체 블록으로 이어지는 짧은 측면 이동.
5. `hama → synthesis`: 적층 블록을 빠져나오며 다섯 구조물이 보이는 전체 테이블로 전환.

## 프레임 인계 체크리스트

1. 첫 장면을 제외한 클립은 직전 승인본의 실제 마지막 프레임을 시작 이미지로 사용한다.
2. 앞 클립을 재생성하면 이후 체인을 모두 다시 생성한다.
3. 로고·가짜 문구·실제 UI가 새로 생기지 않았는지 확인한다.
4. 데스크톱과 모바일의 오브젝트 위치와 이동 방향이 같은지 확인한다.
5. 인코딩 후 이전 마지막 프레임과 다음 첫 프레임의 SSIM이 0.99 이상인지 검증한다.
6. 승인 전 다음 클립을 생성하지 않는다.
