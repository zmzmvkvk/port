# autoresearch 세션 — roomy.page 모바일 텍스트 모션 랙

새 에이전트가 이 파일만 읽고 이어받을 수 있도록 유지한다.

## 무엇을 하고 있나

roomy.page(소스: `web/`, Next.js 정적 export → Cloudflare Pages)에서
모바일 텍스트 등장 모션(카드 전환 시 이름 모프 + 인트로 헤딩 리빌)의
프레임 드랍을 제거하는 Inner Loop.

## 환경 주의사항

- Chrome MCP가 없는 환경이라 스킬의 eval을 **Playwright**로 이식했다.
  헤드리스 Chromium은 WebGL을 SwiftShader(소프트웨어)로 돌릴 수 있어
  절대 fps는 실기기보다 낮다. **상대 비교(베이스라인 대비)만 의미 있다.**
- eval 설정(390x844 DPR3, CPU 4x 스로틀, 휠 델타 800)은 베이스라인 이후
  고정. `eval/` 파일은 Inner Loop가 수정 금지.

## 사이클 절차

1. `outer/program.md`의 가설 백로그에서 하나 선택.
2. `web/` 코드 수정 (한 번에 하나의 가설).
3. `cd web; npm run build` (out/ 재생성).
4. `cd autoresearch; node eval/measure.mjs --label <실험명>`
5. `node eval/score.mjs` → SCORE 확인.
6. 개선 → `git add -A; git commit -m "experiment: ..."` (keep)
   악화/동일 → `git reset --hard HEAD` 전에 워킹트리 복구
   (커밋 전이므로 `git checkout -- web/`), 기록만 남긴다.
7. `inner_results.tsv`에 한 줄 추가 (실패도 기록).

- 카드 아트 교체 (2026-08-18): 아홉 장을 컷 페이퍼 정물 한 세트로 다시 만들었다.
  로컬 grok 프록시(`web/scripts/generate-cards.mjs`)로 생성 → `convert-cards.mjs`로
  768x512 webp. 전/후: `shots/cards-before.png`, `shots/cards-after.png`.
  세트 무게 199KB → 136KB (엔트리 타임라인이 이걸 기다린다).
  - 배운 것 하나: `public/`에 고정 파일명으로 두면 그림을 갈아 끼워도 캐시가
    옛것을 계속 내준다. 배포는 정상인데 라이브만 옛 그림이었고, `?x=1`을 붙이면
    새 그림이 나와서 잡았다. 지금은 `components/ring/cards/`에서 import 해
    내용 해시가 URL에 박힌다. `probe-cards.mjs`가 라이브에서 이걸 검증한다.
  - 배운 것 둘: 그러면서 `p.file`이 파일명이 아니라 절대 URL이 됐는데,
    `atlas.js`가 앞에 붙이던 `/`가 `//_next/...`(프로토콜 상대)가 되어 카드가
    전부 새까맣게 나왔다. 스크린샷으로 잡았다 — 콘솔 에러만 봤으면 놓쳤을 것이다.

- 타이포·모프 교체 (2026-08-18): goo 멜트를 걷어내고 릴레이 하나로 통일,
  서체는 Freesentation(OFL 1.1) 서브셋으로 교체. **75.93 → 81.85** (3회 평균,
  편차 0.23; 직전 커밋은 77.2대).
  - 점수가 크게 뛴 곳은 모프가 아니라 **idle 까지** 였다. morph p95 66.7 →
    50.1ms, idle p95 66.7 → 50.1ms, idle 19.2 → 20.9fps. SVG 필터 서브트리와
    `will-change: filter` 레이어가 아무것도 안 움직일 때도 합성기에 비용을
    물리고 있었다는 뜻이다. 모션을 덜어냈더니 정지 상태가 같이 빨라졌다.
  - 서체: Satoshi/Geist 는 한글 글리프가 아예 없어서 링의 한국어 이름이 전부
    시스템 폰트로 떨어지고 있었다. 한 패밀리로 통일하면서 그게 사라졌다.
    원본이 2.5MB짜리라 `web/scripts/subset-fonts.py`로 실사용 문자만 남겨
    굵기당 53KB. 엔트리가 `document.fonts.ready`를 기다리므로 이 무게가
    첫 화면에 그대로 실린다.
  - **하네스 주의**: `eval/measure.mjs`는 모프 구간을
    `span[style*="will-change"]` 아래의 분수 opacity 로 잡는다. 락업의 래퍼
    span 에서 그 속성을 떼면 morphMisses 가 나서 점수가 무너진다. 지금은
    `will-change: transform, opacity` 로 남겨 두었다.
  - `smoke-desktop.mjs`가 지키던 것이 뒤집혔다. 예전엔 "데스크톱에서 goo가
    살아있는가"였고 지금은 "필터가 한 번도 안 켜지는가 + 릴레이가 도는가"다.

- 인트로 헤딩이 카드에 가려지던 것 (2026-08-18): 사용자 제보. 헤딩이 링의
  눈(hole) 안에 놓이도록 설계돼 있었는데, 원본 문구가 짧아서("Works '26")
  들어맞았던 것이고 "김서준 — Works"는 구멍보다 넓다. 그래서 어느 폭에서든
  첫·끝 글자가 1초 넘게 카드 뒤에 있었고, 폰에서는 "김"이 엔트리 내내 잘려
  이름 자체가 깨져 있었다. 두 군데를 고쳤다.
  1. 위치 — 링 안이 아니라 링의 바깥 반지름 위로 올렸다(`textGap`). 구멍에
     맞춰 줄이는 방법은 폰에서 15px가 되어 버려서 못 쓴다. 위에 그리는 방법
     (renderOrder 뒤집기)도 안 된다 — 카드 아홉 중 셋이 먹색 바탕이라
     검정 글씨가 그 위에서 사라진다.
  2. 퇴장 시점 — `textOutAt`이 "링이 도착한 시각 기준"이었다. 그래서 링이
     4.46배로 커지며 화면을 쓸고 지나가는 2초 동안 헤딩이 만강도로 서 있었다.
     "링이 출발하는 시각 기준"으로 바꾸니 같은 교차가 "쓸려 지워지는" 것으로
     읽힌다. 원래 주석이 말하던 sweep 이 그제야 실제로 sweep 이 됐다.
  - 검증: `probe-entry.mjs` (비동결) — 390/708/1024/1512 네 폭에서 헤딩이
     온전히 읽히는 구간과 지워지는 구간을 눈으로 확인. 정지 화면 스크린샷은
     바이트 동일, Frozen Metric 81.89 로 변동 없음.
